# 强力删除（Force Delete）

一个轻量级 Windows 桌面工具，用于强制删除因权限、占用、系统保护等原因无法通过资源管理器删除的文件/文件夹，并按关键词清理软件卸载后的注册表残留。

- 单文件 exe，免安装、无需 Python 环境，解压文件夹后双击exe文件即可启用
- 启动自动申请管理员权限（UAC）
- 无联网、无注册表自启、无后台驻留，关闭即退出
- 支持把文件/文件夹拖进窗口，或把文件拖到 exe 图标上直接启动

---

## 一、文件强力删除原理

删除不是"一次尝试"，而是一条逐级升级的流水线，前一级失败才进入下一级，每一级都校验实际结果，而不是只看命令返回码。

### 1. 清除文件属性

调用 `attrib -r -s -h` 去掉 只读 / 系统 / 隐藏 属性（文件夹加 `/s /d` 递归处理子项）。

这类属性经常是"删不掉"的表层原因——资源管理器只会提示"需要权限"。

### 2. 夺取所有权与权限

```
takeown /f <路径> /a /r /d y
icacls <路径> /grant *S-1-5-32-544:F *S-1-5-18:F /t /c /l /q
```

- `takeown` 把所有权转给 Administrators 组
- `icacls` 授予 Administrators（S-1-5-32-544）和 SYSTEM（S-1-5-18）完全控制
- 使用 **SID 而非组名**，保证在中文、英文及非中文系统上都生效（中文系统里组名是"Administrators"以外的本地化名称，按名字授予会失败）

### 3. 结束占用进程（Restart Manager）

调用 Windows 原生 **Restart Manager API**（`rstrtmgr.dll`）而非自己枚举句柄：

- `RmStartSession` → `RmRegisterResources` → `RmGetList` 得到占用文件的进程/服务
- `RmShutdown(RM_FORCE_SHUTDOWN)` 强制结束

相比 `taskkill` 或遍历句柄，RM 是系统官方机制，能识别服务、跨会话进程，准确率高。

安全处理：
- 不会结束本程序自身
- 若被结束的是 `explorer.exe`，会自动重新拉起资源管理器
- 目录会展开为内部文件列表再注册（RM 只接受文件路径），单次最多 1000 个文件

### 4. 三级删除策略

| 级别 | 方法 | 针对场景 |
|---|---|---|
| 1 | `os.remove` / `shutil.rmtree` | 普通情况，遇到只读文件自动去只读后重试 |
| 2 | 加 `\\?\` 前缀再删 | 路径超过 260 字符、以点/空格结尾、`CON`/`NUL` 等保留设备名 |
| 3 | 先改名到同目录随机名，再删 | 句柄仍被占用但允许改名的文件（改名后原句柄失效） |

每级完成后都会用 `os.path.lexists` 复查，`shutil.rmtree` 静默残留也会被识别。

### 5. 重启后删除（终极兜底）

仍删不掉时调用 `MoveFileExW(path, NULL, MOVEFILE_DELAY_UNTIL_REBOOT)`，写入系统的 PendingFileRenameOperations 队列，由系统在下次启动早期（smss 阶段，多数驱动尚未加载）删除。完成后界面会询问是否立即重启。

### 特殊对象处理

符号链接、目录联接（junction）只删除**链接本身**，不会递归删除其指向的真实内容，避免误删。

## 二、注册表残留清理原理

按关键词通用扫描，不绑定任何特定厂商。

### 扫描范围

| 类别 | 位置 |
|---|---|
| 卸载信息 | `HKLM/HKCU\SOFTWARE[\WOW6432Node]\Microsoft\Windows\CurrentVersion\Uninstall` |
| 启动项 | `HKLM/HKCU\SOFTWARE[\WOW6432Node]\Microsoft\Windows\CurrentVersion\Run`、`RunOnce` |
| 系统服务 | `HKLM\SYSTEM\CurrentControlSet\Services` |
| 软件厂商键 | `HKLM/HKCU\SOFTWARE[\Wow6432Node]` 顶层键、`HKCR` |
| 深度扫描（可选） | 遍历 `HKLM\SOFTWARE`、`HKCU\SOFTWARE` 全树 |

匹配规则：
- **键名匹配** → 生成"整键删除"项，并剪枝（父键删除后不再遍历子键）
- **值数据/值名匹配** → 只生成"删除该值"项，保留所在键（避免因一个路径字符串误删整个容器键）

### 安全机制

1. **系统关键键黑名单**：约 30 条核心路径（`HKLM`、`HKLM\SOFTWARE`、`...\Microsoft\Windows`、`SYSTEM\CurrentControlSet`、`Services` 根等）。即使输入 `microsoft`、`software` 这类危险关键词也不会被列为删除项。
2. **删除前备份**：默认对每一项执行 `reg export` 导出 `.reg` 到 `backups\reg_<时间戳>\`，双击即可还原。可勾选关闭备份（关闭后会有醒目提示）。
3. **删除结果校验**：不只看 `reg delete` 返回码，还会重新打开键/值确认确实已消失。
4. **失败自动夺权**：常规删除被拒时，开启 `SeTakeOwnershipPrivilege`，通过 `SetNamedSecurityInfoW` 把键的所有权转给 Administrators 并授予完全控制，然后重试。
5. **扫描上限**：单次结果最多 800 项，深度扫描最多遍历 30 万个键，防止界面卡死。

## 三、功能与界面

程序有两个页签，底部共享执行日志。

### 页签 1：文件强力删除

- 添加文件 / 添加文件夹 / 移除选中 / 清空列表
- 拖拽文件或文件夹到窗口
- 列表支持横向滚动条（超长路径可完整查看）
- 双击条目或按 `Delete` 键移除
- 三个选项，默认全开：
  - 自动结束占用进程
  - 自动夺取所有权与权限
  - 仍删不掉时安排重启后删除
- 点击"立即强力删除"，二次确认后执行；删除成功的条目自动从列表移除

### 页签 2：注册表残留清理

- 关键词输入（空格 / 逗号 / 分号分隔，可多个），回车即扫描
- "深度扫描（慢）"可选项
- 结果区：
  - 关键词**黄色高亮**
  - 单击切换单行勾选
  - **按住左键拖出蓝色范围带**，松开后统一勾选/取消，快速批量选择
  - 横向滚动条
- 全选 / 全不选
- "删除前自动备份 .reg（推荐）"开关
- "备份管理"窗口：查看每个备份的大小与总占用，删除选中 / 全部删除 / 打开目录

## 四、注意事项（重要）

1. **删除不可恢复**：文件不进入回收站。确认前请核对列表。
2. **不要删系统关键文件**：本工具不阻止你删除 `C:\Windows`、驱动文件等，删了会导致系统崩溃。
3. **占用进程会被强制结束**：若占用者是正在编辑文档的 Word，未保存内容会丢失。
4. **注册表删除风险更高**：请逐项核对，只删明确带目标软件名称/厂商标识的项；保留默认备份，出问题双击 `.reg` 还原。
5. **需要管理员权限**：启动时请求 UAC。若取消，程序仍可运行，但夺权、结束进程等能力受限，状态栏会提示"权限受限"。

### 为什么有的文件仍然删不掉

有些文件即使拿到管理员权限也无法删除，通常不是"权限不够"，而是被更底层的力量拦住：

- **内核级保护驱动**：部分安全软件与系统保护组件会加载内核驱动或文件系统微过滤驱动（minifilter），在内核层直接拦截删除、改名、夺取所有权，甚至阻止写入重启删除队列
- 此时表现为 `WinError 5 拒绝访问`，管理员权限无效，**任何纯用户态工具都无法绕过**
- 应对方式：先关闭对应软件的自我保护或正常卸载，重启后再删；无法关闭时进入**安全模式**（Shift + 重启 → 疑难解答 → 高级选项 → 启动设置 → 重启 → 按 4），保护驱动不加载，可正常删除；终极方案是 WinPE 启动盘

其他常见原因：

- 文件被系统进程或服务独占，且不允许结束
- 磁盘处于只读 / 写保护状态，或文件位于受保护的卷、虚拟磁盘
- 权限继承异常（ACL 损坏），连 Administrators 也无权访问
- 文件系统本身损坏，需要先运行 `chkdsk`
